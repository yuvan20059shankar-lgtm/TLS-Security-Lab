STEP 1 OF 5 • CONCEPTUAL OVERVIEW

Step 1: Client Hello (Negotiation Initiation)

The browser initiates the secure communication by sending a Client Hello message. It proposes the highest TLS protocol versions it supports, a list of supported cryptographic cipher suites, a client key share (in TLS 1.3), and a cryptographically random number (Client Random) to prevent replay attacks.

STEP 4 OF 5 • CONCEPTUAL OVERVIEW

Step 4: Key Establishment (Diffie-Hellman / ECDHE)

The client and server use the Elliptic Curve Diffie-Hellman Ephemeral (ECDHE) key exchange algorithm. Both sides combine their private secrets with each other's public shares to compute an identical symmetric session key without ever transmitting the master secret across the wire.

Client Math
Private key: a (secret)
Public share sent: A = g^a mod p
Shared Secret: S = B^a mod p
Session Keys Established
Derived via HKDF (HMAC-based Extract-and-Expand Key Derivation)
Server Math
Private key: b (secret)
Public share sent: B = g^b mod p
Shared Secret: S = A^b mod p
Symmetric Session Key (AES-256): 0x3F8A2D9B71C04E6E1A8F532B094C82D714E89B23190A...
STEP 5 OF 5 • CONCEPTUAL OVERVIEW

Step 5: Secure Communication (HTTPS Tunnel Active)

The TLS Handshake is complete! The browser and server switch to fast symmetric encryption (AES-256-GCM). Every byte transmitted across the internet is encrypted for confidentiality and authenticated with an integrity MAC to prevent tampering.

FEATURE 6

TLS 1.2 vs TLS 1.3 Architecture Comparison

Explore why the IETF overhauled the TLS protocol in RFC 8446. Toggle between versions to compare handshake round trips, cipher suite deprecations, and forward secrecy guarantees.

Active Comparison Target:
TLS 1.3 (RFC 8446)

Ultra-Fast 1-RTT Handshake with Zero-Round-Trip Resumption

TLS 1.3 eliminates the second round-trip by sending Diffie-Hellman key shares in the initial Client Hello. All legacy weak ciphers (RSA key exchange, RC4, 3DES, CBC mode) have been removed, making forward secrecy mandatory.

1 RTT Handshake Round Trips
5 Ciphers Modern AEAD Suites Only
100% PFS Mandatory

            Stage 1 / 5

            3–5 Minute Presentation Cheatsheet

            Step 1: Client Hello

            Speaker says: "The browser says 'Hello' and offers its supported TLS versions (TLS 1.3), cipher suites, and a client random number. This initiates the negotiation."

            Step 2: Server Hello

            Speaker says: "The server picks the strongest compatible cipher suite (TLS_AES_256_GCM_SHA384) and sends back its own random number to agree on the cryptographic rules."

            Step 3: Certificate Verification

            Speaker says: "The server sends its digital certificate. The browser checks the signature against trusted Certificate Authorities (CAs) to verify the server's identity and stop impersonation."

            Step 4: Key Establishment

            Speaker says: "Using Elliptic Curve Diffie-Hellman (ECDHE), both parties derive the exact same symmetric session keys without ever sending the secret over the network."

            Step 5: Secure Communication

            Speaker says: "With session keys in place, the green padlock turns on. All HTTP data is now encrypted with AES-256-GCM, ensuring confidentiality and integrity."
